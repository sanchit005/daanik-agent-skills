# Contributing to Daanik Everyday AI

Thank you for helping make practical AI more understandable and useful.

## What we welcome
- Clearer instructions and better everyday examples.
- Corrections, accessibility improvements and translations.
- Better prompt triggers and more reliable workflows.
- Evaluation cases that reveal a failure or a safety gap.
- Evidence-backed improvements to behavioural and consumer education.

## Before you contribute
1. Read the root README and the Skill you plan to change.
2. Check existing issues and pull requests to avoid duplicate work.
3. Keep changes focused on one skill or documentation topic.
4. Do not submit personal data, private messages, account details, client records, API keys or confidential documents.
5. Do not include copyrighted course materials, paid question banks, images or datasets unless you have permission to redistribute them.

## Writing standards
- Use plain English and explain technical terms.
- Include when to use the Skill, how to start, a workflow, examples, expected output and limitations.
- Make assumptions and uncertainty visible.
- Preserve user autonomy; avoid coercive or deceptive persuasion.
- Never ask for passwords, PINs, OTPs, CVV or recovery codes.
- Add evaluation cases for meaningful behaviour changes.
- Keep the YAML frontmatter valid and the Skill name aligned with its directory.

## Pull request checklist
- [ ] The change has a clear user problem it solves.
- [ ] Instructions and examples are understandable to a non-specialist.
- [ ] Safety and privacy implications have been reviewed.
- [ ] No claims, facts, links or sources have been invented.
- [ ] Relevant evaluations have been added or updated.
- [ ] Copyright and licence notices have been preserved.
